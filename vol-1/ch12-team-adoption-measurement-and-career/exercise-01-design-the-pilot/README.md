# Exercise 1 — Design the pilot

Draft a one-page charter for the Relay team before reviewing the synthetic results.
This exercise is a tabletop design. Use fictional task IDs and data.

1. Choose two categories from Relay's backlog. Use docs grounded in current
   behavior and small changes to triage with existing acceptance fixtures.
2. For each category, invent two comparable tickets and an acceptance check
   that applies to both. Record the baseline tools and an assignment rule
   that runs before people see which condition they get.
3. Name an owner, a champion, a reviewer and a decision date. Specify the
   eligible workspace, excluded data and effects, and the quality follow-up
   window. State what you will do with work open at cutoff.
4. Write what would cause you to pause, extend or consider expansion. Include
   review capacity and a precise definition of an escaped defect. If you use
   your own thresholds, explain the decision each is meant to support.

## Verify

Have someone apply the charter to one candidate in each category. They should
be able to say whether it belongs, which completion check applies in each
condition, who can stop the pilot and what an abandoned attempt counts toward.
Use the [example charter](solution.md) to review your own draft if working alone.
